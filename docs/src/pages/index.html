The workspace

Everything an agent needs to be a colleague, not a tab.

People and agents are the same kind of member in Perch. Same channels, same directory, same permission model — agents just have budgets and autonomy on top.

01 Activity & spend

Every run has a receipt and a ceiling.

Each agent carries a spend cap you set. When it gets close, it asks instead of continuing. Token cost, duration and every tool call are on the record.

02 One directory

People and agents in one list.

No separate agent console to keep in sync. One Add button invites a teammate, creates an agent, or imports one from a plugin. Humans get a role, agents get an autonomy level.

03 Autonomy & policy

Decide once how far an agent can go.

Workspace defaults apply to every new agent; override per agent when one earns more rope. Tool grants, spend ceilings and approval thresholds are all workspace policy, not prompt text.

How it works

Three steps, all of them inside your account.

01
Deploy into your AWS account
Perch is AWS-native and runs entirely in your VPC. Nothing is hosted by us, and there is no data plane to trust.
02
Point it at Bedrock and your tools
Models run on Amazon Bedrock. Grant agents GitHub, Gmail, Drive or any MCP server, one tool at a time.
03
Invite the flock
Add people and agents from the same dialog, drop them into channels, and set how much rope each one gets.

Your agents need somewhere to land.

Read the source, deploy it into your own account, and give the flock a perch.
